# R3A OFD 表格索引与 Rust 拓扑验收报告

日期：2026-10-25。基线为 R2 最终已验收源码，DocVortex 版本保持0.6.1，私有原生协议由38升级至39。

**R3A 本机验收通过。** 四份目标 OFD 表格压力输入的公开解析热耗时中位数之和下降 **36.11%**，逐项下降20.51%–68.78%。41份累计输入完整输出一致，完整测试12464项通过；46份导出输入、350次实际写出及同一ABI3 wheel在Python3.11/3.14的安装验证通过。

## 1. 选定范围

在冻结 R2 上重新 profiling，稀疏文字的60×40网格主要耗在 `_logical_cells` 的逐格边全线扫描，多表和噪声输入主要耗在 `_components` 两两线段比较。普通真实 OFD 的这两阶段占比低，纯向量页回退不进入表格内核。本批收益集中在复杂表格，不能推广为全部 OFD 都有36%的收益。

Rust核心位于 `rust/docvortex-core/src/ofd_tables.rs`，PyO3绑定位于 `rust/docvortex-python/src/ofd_tables.rs`，Python接入位于 `src/docvortex/analyzers/native/ofd/table.py`。

- 线段按方向分列、按坐标稳定排序，通过保守区间查询筛选连接候选；最终相交/共线谓词继续使用原0.6/0.8容差和浮点操作。
- 连通分量使用原输入索引和最小索引根，保持分量顺序、成员顺序及Python对象身份。
- 基础格按原右邻、下邻顺序计算边状态，同一网格的对齐区间可复用。保留完整边、缺失边、局部边三态，以及已有边绕路连通、非矩形区域的拒绝逻辑。
- 单元格恢复只返回整数行列范围，再构造原 `OfdTableCell`。文字、图片归属、内容消耗集合、候选排序、重叠筛选及HTML物化保持原实现。
- Python继续负责线段规范化、坐标聚类和浮点平均，避免改变不同Python运行时的求和行为。文字Delta、矩阵、quad、clip和字形几何未纳入本批。
- PyO3传入自有数值快照，计算期间释放GIL，不逐线回调Python。无新增Cargo依赖。

默认数据、计费方法及数值合同满足时使用原生路径；自定义预算子类/计费方法、相交/坐标/区间/覆盖钩子、容差、单元格类型、未知方向、非有限或超安全整数范围数据保留原Python行为。

## 2. 保留原比较预算

`OfdTableBudget` 在整份文档跨页累计。索引减少实际计算，但没有减少预算计费：

- 连通分量仍计入全部 `N*(N-1)/2` 个原始配对。
- 每条内部边仍先计入原本扫描的全部分量线段，再使用缓存或判断局部边；首次局部边拒绝之后不提前计费其它边。
- 超限时恢复原首次失败的计数并抛出原 `OfdResourceLimitError` 和完整消息。已经超限的初值仍按原行为只加一，零比较不主动检查预算。
- 自定义计费方法继续逐项执行，避免批量计费绕过其可观察行为。

默认两百万预算的80×80大网格回归确认：优化前后都在 **2,000,001** 次处失败，不能把原先拒绝的输入变为成功。

## 3. 数值边界修正与最终身份

初版索引仅对 `coordinate +/- 0.6` 的结果端点外扩一个ULP。数值审查发现：`abs(-0.6 - 1e-17)` 舍入为0.6，原谓词接受这两条线，但 `-0.6 + 0.6` 抵消为零，对零仅外扩一个ULP会漏掉正侧微小坐标。该问题同时影响连接候选和格边对齐。

新增回归对初版扩展复现 **6 failed、2 passed**，包含正负两侧、极小坐标、输入反序和规范化后的线段。最终实现先将容差半径外扩一个ULP，再对计算后的查询端点外扩一个ULP，最终精确谓词保持不变。另加Rust定向回归，修复后全部通过。
