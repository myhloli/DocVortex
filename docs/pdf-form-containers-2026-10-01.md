# 页面 Form 容器识别与 Issue #23 验收

## 规则与边界

[Issue #23](https://github.com/myhloli/DocVortex/issues/23) 的两份原件均有整页声明 `/BBox` 的外层 Form；PDFium 返回的实际内容边界比声明框小。只用内容边界和框内文字行数判断图片，会提前认领正文和表格。

`document/pdf/form_structure.py` 在页面锁内关联 PDFium 对象与真实内容流的 `Do` 调用，保存实例、祖先、累积矩阵、可见剪裁、声明框、实际内容框及原字符／Path 编号。重复调用分别编号；临时对象地址不会进入快照。资源缺失、循环、调用树或矩阵不一致时关闭该结构的展开判断。资源 reader 按文档惰性创建，关闭文档时释放。

`analyzers/native/pdf/form_roles.py` 在表格、图形、图注认领之前统一判断页面角色：

- 声明框映射与 MediaBox 或 CropBox 各边误差不超过页面对应尺寸的 2%，只是必要条件。
- 排除内部栅格图、独立子 Form 和统一绘图核心后，要求稳定栏缘、长行与连续正文；或多个不同图题和独立空间区域支持的图表。
- 稀疏／表格页需要同文档已确认的页面映射，同时匹配稳定栏缘或重复表格格线，再由正文或原生表格成员支持。
- 满页绘图、多面板图片、密集标签、共同图题及图题与统一绘图核心冲突时保留整图。多个遮罩按并集排除标签，不用图片数量判断角色。
- 图题不能提前拆开仍保留的页面 Form。保留 Form 的图片选择允许实际内容覆盖整页。

展开只改变私有分析视图：提升直接子 Form，扣除已展开祖先的分析深度，清除外层表格／绘图／图注屏障。字符认领、边界收紧、图题合并和后续补认领均使用对象来源与可见区域。重复位置调用的成员取并集，行仍唯一认领。简单页面矩形仅在首次绘制、没有内部正文或图像并由外部正文支持时作为装饰处理。

公开 `parse`、ModelJson、MiddleJson 和原有 Form／Path 边框查询未改协议。角色规则由 Python 与 Rust 共用；Rust 增加字符归属批量读取，非标准 ABI 或旧扩展可使用逐字符参考路径。本轮保留 Image XObject，不涉及栅格背景识别、OCR 或 VLM。
