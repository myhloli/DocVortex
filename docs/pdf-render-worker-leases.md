# PDF 渲染任务租约与空闲文档缓存

`PDFRenderSession` 保存共享输入文件、参数和取消状态；worker 使用权只持续到一次 `render()` 完成。进程池继续受既有全局预算约束，默认最多三个 worker，池的范围是当前宿主进程。

## 调度与缓存

- 等待请求按 FIFO 获取租约，归还、取消和池关闭通过条件变量唤醒等待者。有其他请求排队时先分配一个 worker；请求不会持有部分 worker 再等待更多额度。
- 空闲 worker 优先按文档身份复用，其次选择无缓存的 worker，最后替换其他文档的缓存。每个 worker 最多保留一个 PDFium 文档。
- 渲染结果全部收到并物化为独立图片后，归还所有任务租约。空闲缓存不阻止其他文档使用进程；模型推理不持有渲染租约。
- 跨文档切换先发送 `close` 并确认旧输入释放，再发送 `open`。输入文件、常驻进程、原始像素传输和裁图算法继续复用。

## 关闭与异常

缓存归属和任务租约归属分别登记。A 的缓存正由 B 替换时，A 关闭会等待旧输入释放确认；它不会取消 B，也不会在确认前删除输入文件。B 已经打开自己的输入后，A 的关闭不再触碰该 worker。

任务取消、打开或切换失败、活动进程崩溃会终止对应 worker 并归还额度。空闲进程崩溃只使缓存失效，下次请求可以重建。全池关闭直接回收活动进程，不向另一个线程正在读取的活动管道插入关闭命令。

legacy 后端仍不得与活动 session 渲染并行叠加进程预算，但可以替换空闲缓存；未关闭的 session 随后可重新加载输入。等待预算的请求在真正取得额度后再次检查后端互斥状态。

## 接口与诊断

公开调用签名不变，`auto` 后端选择不变。`worker_diagnostics` 继续累计实际打开输入的记录，同文档命中缓存不增加打开次数。`close_diagnostics` 记录缓存被替换或文档关闭时的输入释放；强制进程回收记录额外包含 `worker_terminated: true`。

内部 `_workers` 仅表示该 session 当前任务的租约，正常 `render()` 返回后为空；worker 进程仍可在全局空闲池中存活。文档关闭仍确认自己的所有输入句柄已释放，然后删除临时文件。

## 回归覆盖

测试覆盖同文档缓存亲和性、五份打开文档共享三个进程、FIFO 与队首取消、等待超时、活动和空闲进程崩溃、切换失败、旧会话关闭与缓存替换竞态、新旧后端切换，以及完整页像素、旋转、透明度、裁图编码和图像所有权。

性能验证分别检查无竞争时的缓存收益、真实 PDF 输出摘要和连续处理的进程树 RSS。模型调用未参与这些渲染基准，不能将其耗时直接解释为完整解析或在线服务的吞吐。

### 本地验证（2026-09-28）

- PDF 相关回归（含真实 MinerU 五文档推理屏障）：386 passed；MinerU session 与窗口专项：21 passed。五文档均能在任一解析结束前进入推理等待，此时渲染租约为零。
- 冻结基线为 `31654b8` 的原渲染模块，其余代码与原生扩展保持相同。32 PDF／299 页、4 页窗口，以及额外 64 页和逐页窗口，输出像素摘要全等，同文档打开次数保持一致。
- 32 份样本预热后各测五次，渲染 CPU 时间中位数之和为基线 4.749384 秒、候选 4.749379 秒。独立进程墙钟计时有明显噪声；一份两页财务表在初测和反序复测仍超过 5%，同渲染实现与资源路径下交替配对 31 次后为 +0.15%，不将初测或复测结果删除，也不据此声称完整解析提速。
- 两份真实 PDF 各连续五轮、16 页窗口、三个 worker：进程树峰值 RSS 中位数比例分别为 114.27% 和 82.67%，中位与最大峰值均通过既有 130% 门槛。进程身份稳定、输入释放通过，关闭池后渲染进程全部退出。有限回放不代表无限运行无泄漏。
