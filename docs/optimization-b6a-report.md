## 2. 优先级决定与实现边界

实施前复现了既有入口差异：以 `%PDF` 开头、末尾带有效 DOCX ZIP 包的输入，字节入口返回 `pdf`，路径入口返回 `docx`。MHTML 头与 ZIP 尾包也有类似差异。因此本批统一有界文件头的读取，不统一这类混合输入的判型优先级。

| 入口 | 保留的判定顺序 |
| --- | --- |
| bytes | PDF → RTF → MHTML → OFD → EPUB → OOXML → ODF → OLE → Magika 与回退 |
| path | RTF → OFD → EPUB → OOXML → ODF → OLE → PDF → MHTML → Magika 与回退 |

路径入口先保存 128 字节头部，识别 RTF 后仍执行原有容器验证，再使用已读头部判断 PDF。没有新增按 ZIP 文件头过滤的捷径，带任意前缀的合法 ZIP 包仍能识别；普通 ZIP 尾包没有文档身份时，PDF 仍回退到 PDF 结论。PDF 检测仍只检查四字节签名，不在此阶段新增正文可解析性验证。

OLE 私有路径探测先读八字节；非 OLE 立即返回，命中后回到起点读取完整内容，沿用原有字节解析器和内部 stream 判型。这里仍完整读取真正的 OLE 文件，没有扩大为 OLE 解析器重构。无缓冲句柄使“读 magic → 回到起点 → 整读”无需拼接缓冲前缀和剩余正文。

## 3. 测量方法

输入、源码、依赖和扩展身份均冻结。参考为 `B04/candidate-source`，最终候选为 `B06A/candidate-source-final`。基准复用 B0 的身份校验、完整输出指纹和 RSS 采样逻辑，另有本批专用识别驱动。

- 每个场景六对 AB/BA 平衡进程；各进程单列首次调用，再测五组热调用，每组 100 次，64 MiB 场景每组 20 次。表中热耗时是 30 组每次调用平均耗时的中位数。
- 正式计时不包含输出校验、读取审计、tracemalloc 或 RSS 采样。首次调用是在新进程中的第一次识别，包含惰性导入；没有清空操作系统文件缓存，不声称是物理磁盘冷读。
- 读入量在另一进程包装真实文件的 `read()`，统计实际返回字节，包含多个 ZIP 探测的重复尾部读取。这是应用层读取量，不是磁盘物理 I/O。
- 分配在预热与回收后测单次入口的 tracemalloc 峰值。RSS 使用另一进程、固定 100 次独立调用、每次前回收对象，按 50 ms 采样同一时刻的进程树总量。短时峰值可能漏采，不能将分配减少等同于全部进程内存的等比例减少。
- 输入 SHA256 使用分块读取校验，不在测量前先分配整个输入文件。性能期间没有并行测试、构建或语料回放。
