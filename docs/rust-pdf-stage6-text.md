# PDF 原生内核阶段 6：字符归属连续处理

## 范围与版本

DocVortex `546cb1e`、MinerU `646f5350` 将新鲜同源页面证据的字符归属交由 Rust 自有快照完成，协议为 13。tight-first 归属、稳定距离排序、标点桥接、空白邻接和换行边界沿用参考语义；非标准旋转、外部显式几何和替换后的规则仍使用明确的参考路径。原始 PDFium 字符数独立缓存，不能用去重后的字符数代替。

用户要求串行实施，不使用子代理，速度优先；本阶段同时刻进程树峰值 RSS 门槛为基线的 130%。

## 正确性

32 份 PDF / 299 页使用实际 medium / auto 入口和原基线记录的真实模型调用结果。严格审计比较每次模型输入和完整 AnalysisResult；全部一致，审计记录 444 次 Rust 字符归属调用。计时不执行模型输入哈希，完整输出仍逐次校验。

Rust workspace 12 项测试及严格 clippy 通过；DocVortex 117 项、MinerU 81 项相关测试通过。原 Python 路径另行验证。测试包含随机重叠框的逐字符归属、旋转、自定义规则，以及隐藏字符导致原始计数大于 canonical 计数的情况。

## 正式性能

基线为 DocVortex `3eef2d1` / MinerU `cabe6e34`，均启用既有 Rust。每文档一次预热、五次正式测量，基线和候选逐文档交替；内存独立进程测量。冻结模型返回值的交付开销计入墙钟，不作有利扣减。
