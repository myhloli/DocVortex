## 3. 累计性能与复测

两个源码快照使用相同 CPython 3.14.4、pypdfium2 5.13.0、Pydantic 2.13.5 和固定依赖；不 bump 产品版本。每文档先单列首次调用，再测五轮热调用；按文档交替 AB/BA，超过基线 5% 的正式门禁阶段或 RSS 另作反序复测。序列化、身份核验、计数、渲染与正式计时分离；未并行执行本地构建、全量测试或其他重负载。

| 阶段 | 参考中位数之和 | 候选中位数之和 | 候选/参考 |
| --- | ---: | ---: | ---: |
| 公开 parse | 29.237420 s | 27.539700 s | 0.941933 |
| shared 文字提取 | 2.989758 s | 3.015386 s | 1.008572 |
| shared 文本证据合计 | 3.841766 s | 3.858060 s | 1.004241 |
| shared 表格证据合计 | 2.085832 s | 2.099162 s | 1.006391 |

公开 parse 的 37 个样本均未触发热耗时或 RSS 复测。最慢比率是 demo1 的 0.989809；最大进程树 RSS 观察值为 691.219→699.906 MiB，最大单样本 RSS 比率是合成 CJK 文档的 1.037819，不宣称累计 RSS 降低。

shared 初测 demo1 的文字提取/文本合计/表格合计比率为 1.0963/1.0628/1.0534，反序为 0.9880/0.9904/1.0026；mixed_elements_pages_07_10 初测为 1.1525/1.1384/1.0950，反序为 1.0088/1.0248/0.9948。原始记录均保留，没有用总收益抵消单样本回退。shared 最大单样本 RSS 比率 1.044050；RSS 按 50 ms 采样同一时刻进程树总量，可能漏掉短暂峰值。

**首次调用的缓存条件另行核验。** 原始五轮任务的首次调用总和为 41.3346→49.7637 秒，与热运行相反。检查发现参考包有 222 个有效 CPython 3.14 `.pyc`，候选包仅 41 个；`PYTHONDONTWRITEBYTECODE=1` 不阻止读取已有缓存。没有删除或改写原记录。

随后对全部 37 份文档使用新的独立进程、相同空 `PYTHONPYCACHEPREFIX`，并禁止写入字节码。两边均不能读取现有包或依赖缓存，完整输出仍与冻结基线相同。首次调用总和为 **81.6677→79.8135 秒，比率 0.977296**；最大单样本比率 1.044725，无需触发反序复测。这个序列包含统一的源码编译成本，不能与原始序列的绝对耗时直接比较，也不当作物理磁盘冷读。

实际写出覆盖 8/64/256/1,000 个 4 KiB 素材、三个公开入口和新写/同内容/真实覆盖，共 36 个场景；每方向五次，按相反顺序执行两轮。全部输入、实际文件集合及每个文件字节摘要相同，独立 RSS 重放与计时输出也相同。合并十轮原始耗时后的比率为 **0.792970–1.022597**；所有方向最大 RSS 比率 **1.004607**，没有持续退化。

256 素材的 `export_middle_json/same` 初测比率 1.068734，反序为 0.914508。64 素材的 `save_bundle/same` 正向 0.912705、反序 1.101396，合并中位数比率 1.009155；这个约 7.7 ms 的场景存在执行轮次波动，未在两个方向同时退化。所有原始样本与阶段诊断保留。

## 4. 完整输出、真实导出与视觉

冻结 PDF 集合显式包含 research-report 和 EMNLP 两份 Form 样本、nougat、61 页异常中文度量 guide 及合成边界输入。37 份成功文档共 443 页、521 个素材，完整 ModelJson、MiddleJson、素材路径/字节摘要及全部诊断相同；扫描件的 `pdf_ocr_unsupported` 合同相同。没有排除坐标、空字段、顺序或 producer 字段。

shared 使用共同基线完整 ModelJson 页面冻结的区域集合，两边输入及区域摘要一致。它只证明共享原语在固定区域下的等价性；真实 MinerU 验证另列。

多格式回放覆盖八份真实 OOXML、RTF、ODF、EPUB、MHTML、OFD 输入及两份 HTML 压力输入，共 10 份、36 页。实际导出另取 17 种输入格式夹具和八份真实输入，共 25 个案例、76 页；每个案例都实际写出 Markdown、HTML、LaTeX、DOCX、EPUB、结构化内容和 PDF，并回读 bundle、核对素材、重新渲染 HTML。

双方 350 次渲染的 `render_errors` 均为空，完整渲染诊断相同。实际文件集合相同；原始文件仅 25 个 DOCX 容器不同，逐成员字节完全相同，ZIP 信息仅 `date_time` 不同，详见 `export-raw-difference-audit.json`。没有将它们记为原始字节相同。PDF 原始文件相同，已有逐页文字/尺寸/像素签名检查也通过。

视觉选择研究报告 2/5 页、EMNLP 4/16 页、nougat 2/7 页、guide 1/30 页。八页前后标框像素相同；四组 HTML/旁文件与 ORIGINAL/REFLOW PDF 字节、诊断相同。PDF 导出共 8 页 ORIGINAL、12 页 REFLOW，Poppler 100 dpi 的全部像素相同。

已人工查看八页候选标框、四页原文和八页 PDF 导出。guide 的 ORIGINAL 密集表格仍有既存字体缩小、行跨度换行和底部局部裁切观感；字节及像素与基线一致，本轮未修复该问题，也不宣称提高视觉质量。

随后在 Codex 内置 Chromium 实际打开四组候选 HTML，人工检查首屏、图像、正文及末尾表格，共保存九张 1280×720 截图；图像加载正常，未观察到新增文字、图像或表格变化。HTML/旁文件完整字节相同是独立的前后对照证据；浏览器截图用于可读性抽查，没有将其扩大为所有页面或浏览器的像素证明。

## 6. 测试修正、中间失败与限制

B8 没有追加生产算法修改。累计安装验收发现并修正以下工具/测试集成问题：

1. B0 新基准测试依赖 psutil，但 `test` extra 未声明；补入测试依赖，不修改默认运行依赖。
2. 直接调用 worker 的单测会把 Loguru 的全局禁用状态泄漏到后续诊断测试；用 monkeypatch 隔离状态和环境变量，保留 worker 的实际日志策略。
3. 导出 worker 测试假定 checkout 源码导入；修正为显式包含实际安装包及原生扩展的临时 source snapshot，仍保留独立子进程、来源及身份保护测试。
4. Windows 全量测试发现两项 POSIX 路径断言和一项目录 I/O 异常类型假定；改为平台解析后的路径及底层实际异常类型/errno，产品 I/O 行为不变。修正的三个用例本机通过，随后完整 CI 全绿。

首次本机全量、第二次日志隔离失败、首次 Windows CI 三项失败，以及验收脚本的导出模块路径、非 Git 快照驱动位置、XOR 夹具解码问题均保留原日志。脚本修正不改变产品输出或金标。

日志隔离修正后的本机全量为 11071 passed、14 skipped，82.95 秒；随后平台断言的三个用例定向通过，最终 CI 全绿。CI 各环境因平台条件跳过 16–29 项，六个端点分别通过 11056–11069 项，Pydantic 下界也完整通过。最终 Ruff 检查通过，448 个文件格式一致；两份新增测试文件另统一排版，AST 完全不变。253 个新增函数/方法的中文说明检查通过。详细回归与边界证据见原始文件。
