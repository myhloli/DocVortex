# PDF 原生内核阶段 15：候选成员、网格扩展与动态合并

## 实现边界

实现提交 `6fc883d0a31d55c15e169c862488b9de02c18d6b`，私有协议 20。规则候选核心成员以 Rust 自有集合保存，表注扫描只发起批量包含、交集和差集查询。页面网格与行片段只准备一次，Rust 连续完成网格扩展、共享成员更新、动态首目标合并和注释角色冲突处理，最终仅构造保留的 `_TableCandidate`。

保持按分数稳定降序、扩展后的框参与匹配、首个重叠目标、目标 union 后影响后续匹配、注释行框插入顺序和表体优先规则。保持原旋转往返及相等坐标语义。网格成员缓存有界；超过缓存预算时继续精确计算，不减少候选覆盖。

表题、脚注文字判定与规则候选发现仍在 Python，候选展开中的部分框组装和注释对象也仍是 Python。因此本批不是整个表格/Flash 内核迁移完成。仅内部检测器独占的普通候选采用新路径；特殊数据、覆盖规则和不足两个候选的情况保留原有参考流程。原生计算错误不静默回退。

## 失败版本与修正

初版 `candidate-stage15` 的三样本热点试测完整输出等价，但密集表格首测退化 8.39%，反序复测仍退化，未通过门槛，全部记录保留在 `public-stage15-focus`。

独立 profiler 发现 Python 集合适配器执行了约 214 万次逐成员查询，批量迁移反而增加跨边界开销。`candidate-stage15b` 改为批量交集/差集，并对解析器生成的整数来源 ID 使用整数混合哈希；仍由完整整数相等判定处理碰撞，不改变成员语义。

修正版与协议 19 的同场三样本试测：49.- 从 1.771607 s 降至 1.417446 s（19.99%）；demo1 变化 +0.55%，中文论文2 变化 -0.14%，RSS 基本持平。以上仅用于筛选方案，不代替原始冻结基线的正式验收。

## 正式性能与 CI

基线仍为 DocVortex `3eef2d1` / MinerU `cabe6e34`。每文档预热一次、测量五次，逐文档交替版本，超过 5% 退化反序复测；首次中位数用于总和，进程树 RSS 独立采样，上限为原始基线 130%。Profiler、构建、测试、计时分开执行。

三条入口全部输出一致，首次测量即无超过 5% 的单样本退化，无 RSS 超限，正式驱动均退出 0。以上为相对原始冻结基线的累计收益，不能全部归因于本批候选迁移，也不以跨轮总和波动判断本批的增量收益。扫描 OCR 样本不计入 Flash 文本指标，但仍保留在公开与共享链路中；共享链路冻结模型计算，回放交付开销仍计入。三条链路尚未达到各自降低 50% 的目标。

本批不重标旧版本的冷启动或长期资源稳定性成绩，不表示全量 high/xhigh、WebUI 或发布验收完成。最终三链路各自降低 50% 的目标仍保留，未合并、发布或切换默认后端。
