# PDF 原生内核阶段 8–9：页面级上下标与双仓验收

## 改动及版本

DocVortex `4800650` 将上下标几何和字体等价类保存在 Rust 自有记录中，批次只接收字符整数索引；`ed6db1c` 将该能力接入 Flash。全文几何校准仍在逐页消费之前，修复产生的字符副本显式走参考入口，原生记录随页面消费释放。私有协议 15；基线仍为 DocVortex `3eef2d1` / MinerU `cabe6e34`，均启用原有 Rust。

本轮冻结候选为 `output/pdf/native-kernel-20260927/candidate-stage9` / `mineru-stage8`。冻结时记录前序 HEAD 加 dirty 状态；每份结果包含源码摘要、实际扩展 SHA 和输入摘要。对应已推送检查点为 DocVortex `f8a261b` / MinerU `739ad39f`，后续未完成的工作区改动不进入以下成绩。

## 正式结果

热运行每份文档预热一次、测量五次，逐文档交替版本；超过 5% 时反序复测。内存使用独立运行的同时刻进程树 RSS，门槛按用户要求改为基线 130%。候选显式启用文档渲染会话，基线使用旧入口，图像参数和编码器不变。构建、测试、模型录制、profiler 均与正式测量分开。

三条热运行链路完整结果一致，没有超过 5% 的单样本耗时退化，均通过 130% RSS 门槛。`small_ocr.pdf` 自动分为 OCR，明确排除于 Flash 文本指标；没有把它当成 Flash 文本加速成绩。**三条链路均未达到耗时降低 50% 的目标。**

共享路径只冻结真实模型调用的返回值与输入原地修改，分类、栅格化、证据、原生表格、素材和几何仍实际执行。正式时间包含模型结果交付开销，不进行有利扣减。严格模型输入摘要审计另跑，32 份全部一致。

冷启动每份文档五次新解释器，逐次交替版本，不复用进程池。指标从创建进程到首次实际解析返回，包含解释器/导入、输入及模型回放文件装载、字体初始化和 worker 启动；后续序列化、关闭和真实模型推理不计入。各部分单列，回放装载不从总时间扣除。32 份无初次或持续超过 5% 的退化。它是模型冻结的 PDF 冷启动指标，不是完整真实模型服务启动时延。

原始证据：同目录 `shared-stage9`、`public-stage9`、`flash-stage9`、`cold-stage9` 下的报告，以及对应 `*-summary.json`、`stage9-execution.json`。所有失败和早期实验保留，不回写旧报告。
