需特别验证：线性插值分位数（该模块不是相邻取样分位数）、CPython 版本对应的浮点求和、字体族/Unicode 类别、source 与 loose side-map 的不同来源、稀疏相邻字符修复、跨页样式触发、split shadow、旋转及诊断顺序。配置或自定义输入不支持时明确选择参考路径，计算失败必须抛出。

4. 独立测量热点，再跑三链路正式验收。若几何阶段收益已明显受 PDFium 或表格阶段限制，按独占耗时调整下一批优先级，不为减少 Python 代码量而继续细碎迁移。

## 2. 整体迁移表格候选展开与合并

49.- 的页面准备在独立诊断中约占公开解析的 83%，主要调用是 `_detect_table_candidates()`、`_RuleCandidateDraft.materialize()`、`_expand_rule_table_candidate()` 与 `_merge_table_candidates()`。

让候选、网格成员、注释归属、展开状态及合并更新留在 Rust 中，最终只物化保留的候选。保持现有候选覆盖、按分数稳定排序、首个重叠目标选择、成员集合更新和注释合并顺序。禁止以少计算候选或缩小区域替代迁移。

具体实施边界：

- 建立单页候选上下文，复用已有原生 row/core/annotation 几何及整数行 ID；caption、脚注文字判定先沿用现有语义，将其结果编码一次。
- 将 `_RuleCandidateDraft.materialize()` 的规则展开与 connected-grid 扩展连续接入候选上下文，参与合并之前必须得到与参考相同的最终框和成员，不能拿尚未展开的框提前裁掉候选。
- `_merge_table_candidates()` 按分数稳定降序依次处理，并与已有目标当前框比较；目标 union 后会改变后续命中，不能用初始框的一次批量匹配代替动态合并。保留 `_SharedLineIndexSet` 的精确成员语义及注释合并顺序。
- 所有候选处理完后才按位置稳定排序并导出保留对象。先做候选逐字段、成员、注释和最终表格对照，再测量物化次数与独占成本；若只移动合并而未消除展开成本，不宣称完成整个阶段。

交付：现有 186 个表格区域及全部 demo 的结构/诊断/HTML 等价，另覆盖合并单元格、旋转、脚注和透明路径。算法改进应另提交，不能混进纯迁移验收。
