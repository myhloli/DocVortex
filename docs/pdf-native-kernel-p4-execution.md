## 1. 整体迁移全文几何计划

早期独立低干扰阶段计时中，demo1 / 中文论文2 的 `build_document_geometry_plan()` 占公开解析约 27%；协议 19 的当前比例已降至约 16.5% / 15.5%。阶段诊断不代替正式性能收益，详细函数 profiler 放大的累计比例也不能直接当作加速空间。

风险筛查、样本准备、run 统计、跨页样式校准、来源恢复、canonical 行指标和最终 Y 风险已完成阶段迁移；剩余工作是把 `src/docvortex/analyzers/native/pdf/char_geometry.py` 的 X 修复及 Y 行分析/邻行/修复接入同一 Rust 文档数据。延后布局路径最后一次 Python 字符样本物化，不能每个子阶段重新转换字符字典。原始页与行来源 ID、stable tie、字段更新顺序和全文先后依赖必须保留。

需特别验证：线性插值分位数（该模块不是相邻取样分位数）、CPython 版本对应的浮点求和、字体族/Unicode 类别、source 与 loose side-map 的不同来源、稀疏相邻字符修复、跨页样式触发、split shadow、旋转及诊断顺序。配置或自定义输入不支持时明确选择参考路径，计算失败必须抛出。

几何剩余工作：

1. canonical tight 并集、基线及 Y 风险摘要已完成；继续让后续 Y 行分析复用 anchor ID 和聚类。`_record_line_canonical_metrics()` / `_analyze_lines()` 按宽度和成员数选择 dominant，`_has_document_y_risk()` 按成员数选择；只能共享聚类，不能错误地统一三处裁决规则。
2. 接入 X donor、稀疏修复、行修复汇总；先保留纯数值修复记录，按原插入顺序在绑定边界构造 `CharLayoutGeometry` / `LineGeometryRepair`。
3. 接入 Y 邻行、侵入判定、trim 与 split shadow；复用已经准备好的行与 run，最终仅导出计划字段和诊断。保留 X 修复先于 Y、跨页样式先于来源恢复的依赖。
4. 独立测量热点，再跑三链路正式验收。若几何阶段收益已明显受 PDFium 或表格阶段限制，按独占耗时调整下一批优先级，不为减少 Python 代码量而继续细碎迁移。

交付：完整 `DocumentGeometryPlan` 字段及诊断差分、布局/原文/标框对照、32 份公开/Flash/共享入口回放，以及独立正式计时和进程树 RSS。

## 2. 整体迁移表格候选展开与合并

历史分账中，49.- 的页面准备约占公开解析的 83%。协议 20 当前独立分账显示：公开入口约 1.431 s，表格检测约 0.930 s，其中候选发现约 0.358 s、自有展开/合并约 0.504 s；最终 `_TableCandidate` 仅构造 2 个。这些成本主要集中在密集表格；全语料发现/自有合并合计约 8.09%。后续仍要消除 Python draft、表注证据及部分框组装的开销，但不能把此阶段称为完整表格内核迁移完成，也不能把单样本比例套用于全量优先级。

让候选、网格成员、注释归属、展开状态及合并更新留在 Rust 中，最终只物化保留的候选。保持现有候选覆盖、按分数稳定排序、首个重叠目标选择、成员集合更新和注释合并顺序。禁止以少计算候选或缩小区域替代迁移。

当前实现与下一批边界：

- 已接通 Rust 核心成员与页面网格上下文。下一步统一候选发现和表注所需的 row/core/annotation 数据与整数行 ID；caption、Unicode 标记与字体语义先按原规则编码一次。
- 网格扩展与动态合并已连续执行；下一步让候选区间、分数和来源 ID 留在 Rust，减少逐个 Python draft，并将表注链的几何、成员与标记引用判断接入同一上下文。参与合并之前必须得到与参考相同的最终框和成员，不能拿尚未展开的框提前裁掉候选。
- `_merge_table_candidates()` 按分数稳定降序依次处理，并与已有目标当前框比较；目标 union 后会改变后续命中，不能用初始框的一次批量匹配代替动态合并。保留 `_SharedLineIndexSet` 的精确成员语义及注释合并顺序。
- 已在所有候选处理后按位置稳定排序并导出保留对象；仍需消除 Python 注释及 draft 临时对象。继续做候选逐字段、成员、注释和最终表格对照，再独立测量物化次数与各阶段成本，不用最终候选物化减少代替整个阶段完成。

交付：现有 186 个表格区域及全部 demo 的结构/诊断/HTML 等价，另覆盖合并单元格、旋转、脚注和透明路径。算法改进应另提交，不能混进纯迁移验收。

## 3. 迁移最终布局与跨页规则

继续处理 `_finalize_prepared_page()`、阅读顺序/栏布局、标题段落和正文尺度统计。跨页字体、标题、页眉、水印和参考文献判断仍先收集全局证据再逐页裁决，不能改成独立页面判断。

## 4. 收敛所有权与发布门槛

- 分类当前有独立原始统计快照；仍需与正文原始读取进一步复用，不能声称所有 PDFium 字符读取已经只执行一次。
- 矢量、链接和注释仍需移入不可变 Rust 页面模型；统一文档/页面/文本页/位图/字体回调生命周期与同库运行时锁。
- 补齐全量 high/xhigh 的真实模型录制回放、长文档和图像密集/复杂裁剪样本、长期资源稳定性及实际 WebUI 验收。已有 demo1 high/xhigh 是代表样本。
- 保持三链路各自降低至少 50%、无持续单样本超过 5% 退化、RSS 不超过 130% 的门槛；冷启动单列。尚未满足时保留显式候选和参考后端，不切换默认。
- 最终能力和最低 DocVortex 版本同步进入 MinerU，以实际安装双 wheel 验证 Python 3.10–3.14、ABI3 和跨平台矩阵，再按发布周期退出旧后端。
