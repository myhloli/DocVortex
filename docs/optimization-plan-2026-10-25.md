## 3. 后续 Rust 阶段

首轮去重后重新 profiling，以剩余耗时和转换成本决定实施范围，不直接把优化前的成本占比视为 Rust 可回收收益。

1. **R1 电子表格区域发现**：一次传入起点、连接内容位、语义内容位和合并跨度，批量完成三档 gap 的发现、评分、候选选择和子集筛选。保留最近邻停止、评分容差、gap 偏好及稳定顺序，不逐格回调 Python。
2. **R2 RTF 扫描和组索引**：在 N5 之后判断 lexer 是否仍显著，选择一次 bytes 到组索引或事件批次的接口，保留全部词法恢复与预算合同。
3. **R3 OFD 表格和文字几何**：先索引方向/坐标以减少格边全线扫描，再批量计算拓扑；文字 Delta/矩阵/quad/clip 另立独立子批。

R2已于2026-10-25完成本机验收：一次bytes到组范围的Rust扫描保留完整词法校验及单次预算，正文和公开lexer保持原实现；34份累计热基准输入的完整输出一致，逐样本时间/RSS无超过5%的退化，10份首次调用通过。动态词法路径、完整导出、安装及跨平台边界见R2报告。

## 4. 验收要求

- 输入只生成/复制一次，记录相对名称、后缀、原始路径和 SHA256；基线、候选读取同一份冻结字节。
- 正式计时使用无额外包装的公开 `parse(..., keep_model_json=True)`；完整输出序列化在计时外。Model.predict 的诊断微测单列，不能冒充端到端收益。
- 热运行至少五轮，AB/BA平衡顺序；首次调用和独立进程 RSS 单列。不得与构建、完整测试或其他正式基准并行。
- 完整比较 ModelJson、MiddleJson、素材路径及字节摘要、diagnostics，不忽略坐标、顺序、空字段或 producer。
- 对超过基线 5% 的耗时/RSS 样本反序复测；毫秒级样本同时报告绝对值。稳定退化需定位、调整或回退。
- 真实输入覆盖 DOC/DOCX/PPT/PPTX/XLS/XLSX、RTF、HTML/MHTML、EPUB、OFD、ODT/ODS/ODP；补 CSV/TSV 以及密集/稀疏、重复样式、无表正文、长 RTF 等压力输入。
- 对涉及表格和媒体的真实案例实际写出七种格式并回读 bundle。导出错误不能因前后相同而记作成功。ZIP 容器时间差异单列，逐成员比较；PDF 检查文字、尺寸、像素和必要的视觉抽查。
- 运行每批聚焦回归；累计阶段执行完整测试和静态检查。Rust 批次另执行 core tests、fmt、clippy、匹配扩展重建和平台验收。
- 安装核验记录实际来源。测试、构建、提交、推送、PR、合并、发布各自记账，互不替代。
