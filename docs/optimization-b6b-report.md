# B6B 验收报告：选页重写直接返回实际页号

日期：2026-10-24。本批对照为已验收 B6A → B6B，范围与门禁沿用 [分批优化计划](optimization-plan-2026-10-23.md)。B5 仍待处理。

## 1. 结果

B6B 已完成本机验收。重写核心在导入页面时保留标准化页索引，与 PDF 字节一起返回；成功后不再重新打开原 PDF 计算映射。

- 正常选页准备和完整 parse 的底层文档构造均为 **5→4 次**，其中原输入打开 **3→2 次**。页号标准化由两次减为一次。
- **268 项测试通过**，包括新增 48 项范围、实际页面、回退及资源所有权回归。
- **45 个场景**与 B6A 结果一致：42 个成功场景共 97 页、141 个素材，另有 1 个预期 OCR 拒绝和 2 个非法范围错误。
- 五个样本的选页准备中位耗时下降约 **1.4%–19.8%**；完整解析和 RSS 基本持平，不宣称端到端提速或内存降低。
- 六个代表页的前后重写、标框像素一致；两种 PDF 导出的 **16 页**字节、诊断、页面结构和像素一致，三组 HTML 与旁文件也相同。

生产修改仅限 `src/docvortex/document/pdf/pdfium.py`。公开签名、页范围语法、`prepare_source()`、资源所有权、版面算法、Rust、协议和版本不变。

## 2. 实现与合同

新增内部 `_rewrite_pdf_bytes_with_pdfium_result()` 承接原来的打开、标准化、导入、保存与关闭流程，返回现有 `PdfiumRewriteResult`。原 `rewrite_pdf_bytes_with_pdfium()` 仍只返回字节，异常语义不变；安全字节包装也保持原样。

安全结果入口直接采用核心返回的实际导入页号，删除 `_get_rewrite_page_indices_from_pdf()` 及第二次原文打开。跳过损坏页的回退也使用同一核心结果，并补入探测到的损坏页列表。没有跨层复用借出的 PDFDocument，也没有全局缓存。

以下行为保持不变：

- 页索引排序、去重、越界过滤及旧起止页参数钳制；公开范围继续使用当前 `1-5,8,r3-r1` 语法，无可用页或非法范围按原错误处理。
- 低层空选择返回空字节；安全入口不可重写时返回原文，`used_original=True`、`retained_page_indices=None`。
- 回退只保留请求集合内可加载页，只报告请求集合内损坏页；无可加载页、回退保存失败或空输出时保持原有最终字段规则。
- 正常和回退分支的 `PdfiumFontError` 继续传播；源文档、输出文档、探测页面按原流程关闭。
- 调用方 PDFDocument 在成功、范围错误及新输出包装构造失败时保持原句柄可用；内部创建的文档仍由引擎关闭。

## 3. 打开次数和性能

在计时外包装真实 `pypdfium2.PdfDocument.__init__`，区分原输入、新建输出和重写后输入，并保留对象引用验证显式关闭。五份样本均得到下表结果，全部句柄在调用结束后关闭：

| 入口 | 总构造次数 B6A→B6B | 原输入打开 B6A→B6B |
| --- | ---: | ---: |
| 安全重写 | 3→2 | 2→1 |
| 选页准备，含打开选页结果供后续消费 | 5→4 | 3→2 |
| 完整公开 parse | 5→4 | 3→2 |

同一输入字节预先加载；每个阶段两对 AB/BA 平衡进程，每进程单列首次调用，再测五组热调用。重写和准备每组 20 次，完整 parse 每组一次；下表是每版本十组测量的中位数。准备阶段包含读取选页文档页数以触发真实打开，以及关闭内部资源。完整 parse 包含公开选页和后处理，不包含磁盘读入。

身份、输出序列化、PDF 核验、打开次数和 RSS 均与正式计时分开。性能期间没有并行构建、测试或 PDF 渲染。

| 样本与选页 | 重写 B6A→B6B | 选页准备 B6A→B6B | 完整 parse B6A→B6B |
| --- | ---: | ---: | ---: |
| demo1，1、3 页 | 1.1353→1.0896 ms | 2.3999→2.1977 ms | 164.4695→164.4133 ms |
| research-report，2、5 页 | 0.3737→0.3537 ms | 0.9377→0.7519 ms | 276.7944→276.5186 ms |
| EMNLP，4、16 页 | 2.5522→2.3856 ms | 6.9552→6.8563 ms | 156.7065→156.6002 ms |
| nougat，2、7 页 | 1.2068→1.1506 ms | 2.5501→2.4762 ms | 222.5100→222.5624 ms |
| guide，1、末页 | 2.6640→2.0156 ms | 17.9102→17.2459 ms | 193.2082→192.2969 ms |

五个完整 parse 中位耗时相加为 **1013.6886→1012.3914 ms**，比率 **0.9987**，变化很小，不作为明确的端到端提速结论。本批可靠的收益是删除一次原文打开和重复标准化。

RSS 另用独立进程：短阶段固定 100 次调用、parse 固定 5 次，每次前回收上次对象；按 B0 的 50 ms 间隔采样同一时刻的进程树总量。15 组阶段/样本的 RSS 比率为 **0.9938–1.0122**，基本持平；短阶段可能漏掉瞬时峰值。

热耗时、首次调用和 RSS 均未触发超过 5% 的退化门槛，无需追加反序复测。首次调用最大上升是 EMNLP 重写约 4.93%；首次数据包含惰性初始化成本，未清空操作系统文件缓存，详见原始报告。

## 4. 完整输出与视觉

沿用之前冻结的 38 份 PDF，默认选首尾页，五份性能样本采用上表页号；再给 demo1 增加连续、倒数、重复、部分越界、全选及两个非法范围，共 45 个场景。

42 个成功场景的完整 ModelJson、MiddleJson、素材路径及字节摘要、全部诊断、实际源页映射、全本源属性和 metadata 警告相同，共 97 页、141 个素材。扫描件仍返回相同的 `pdf_ocr_unsupported`，两个非法范围仍返回相同的 `page_range_invalid`。未删除解析结果字段或更换金标。

**原始输入重写 PDF 不是确定性的字节产物。** PDFium 会自动生成 `/ID`，并可能写入当前时间作为新文档的 `/Info/CreationDate`。B6A 自身再次重写同一 caibao1 已复现此现象，证据见 `reference-nondeterminism.json` 和 `reference-repeat-caibao1.pdf`。

43 个有效准备场景中，12 个原始 PDF 字节相同，31 个仅在上述自动元数据处不同。每项均保留两份原始 PDF、SHA256、字段值和全部变化字节区间，核验这些区间之外逐字节相同。没有改写原始文件，也没有将这 31 项记为“字节相同”。完整公共解析产物和最终导出 PDF 的比较不排除任何字段。

视觉选取 research-report 第 2/5 页、EMNLP 第 4/16 页、nougat 第 2/7 页：

- 六页前后重写 PDF 和前后标框 PDF 的尺寸、模式、全部像素一致，页内容与源页映射对应。
- 6 页 ORIGINAL、10 页 REFLOW 的字节、诊断、尺寸、文字、注释/链接字典和像素一致；三组 HTML 与全部旁文件相同。
- 人工查看六个代表页对应的重写或标框页面，并抽看六页导出，未发现本批引入的错页、布局或素材变化；完整像素检查覆盖全部 16 页导出。
- 原文与 PDFium 重写后的文件在五页有既存像素差异，最多约 0.266%；B6A 与 B6B 的重写结果彼此逐像素一致。本批没有将其记作已修复事项。
