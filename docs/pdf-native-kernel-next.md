## 恢复后的优先顺序

### 1. 先关闭本轮验收缺口

- 依据本轮逐文档正式结果定位持续超过 5% 的耗时退化，保留首次和反序复测；先复现再修改，不用新的汇总掩盖失败样本。
- 本轮优先复现四份栅格化失败：`2407.00079v4_origi-10.pdf`、`IEBM_A_2667169_O-5.pdf`、`fund_asset_and_transaction_tables.pdf`、`49.-.pdf`。反序复测分别退化 27.52%、23.01%、10.49%、17.35%；从定向会话的打开/关闭、通信及像素传递分账定位，不能用文字提取收益抵消栅格化阶段退化。
- 修复 Windows 超时测试对 `timeout=1e-9` 的不确定假设：实际建立 worker 后使用可控时钟或确定过期的 deadline，继续验证异常、进程退出和输入资源释放。同步修复 MinerU 同类测试，不修改业务超时以迁就测试。
- 联合安装 CI 的逐文件来源与 ABI 校验已通过，但 9 个任务均在测试收集时因 `_span_test_utils` 无法导入而停止。保留 `python -I` 与 `--import-mode=importlib`，仅显式开放该测试辅助模块所在目录，避免将仓库源码重新放入导入路径；修复后重跑全部组合，不能将“来源校验通过”称为集成测试通过。
- 为协议 12 再构建实际 wheel，独立安装 DocVortex 与 MinerU；核对包来源、协议、扩展摘要和全部 wheel 文件，运行三平台安装与正确性矩阵。已有协议 11 wheel/CI 结果不代替协议 12 验收。
- 将语义不变的最终二进制纳入完整三方字符回放，补充 xhigh 真实共享入口及浏览器/真实模型集成。已有 medium/high 冻结回放不等于全部档位完成。

交付：可审阅提交、完整差异清单、跨平台 CI 与实际双 wheel 组合证据；功能、性能、CI 和发布状态分别报告。

### 2. 补齐 P0 的全链路分账

- 建立第三条完整 MinerU 共享链路的冻结模型输出回放，实际包含栅格化、字符提取、文本证据、原生表格和素材处理；模型推理单列。现有文本/表格原语和输入服务基准仅作为阶段诊断。
- 为导入、字体初始化、PDFium 读取与渲染、Python 对象物化、Rust 计算、IPC、复制、编码建立可核对的分账，区分独占时间与嵌套累计时间。
- 独立测量新进程冷启动；预热仅复用正常运行时及进程池，不复用前一文档的分析结果。将 32 PDF／299 页扩充到长文档、扫描、图像密集和复杂裁剪样本。
- 对三条链路分别计算逐文档中位数之和，并报告 PDFium 固定工作量所限制的加速上限。若实际可优化占比不足以达到 2 倍，明确目标差距，不调整口径。

交付：三链路统一基准及全量输出、时间、同时刻进程树峰值 RSS 报告。

### 3. 完成原生数据所有权和分类复用（P1/P2）

- 将矢量、路径、链接与注释从 Python 兼容存储迁入不可变 Rust 页面模型；算法层保留整数来源 ID，不接触 PDFium 指针。
- 在同一 PDFium 库与运行时锁下逐步迁移文档、页面、文本页的所有权；用异常退出、重复关闭、回调失败和关闭后访问快照验证生命周期。
- 分类先新增原始统计批次，保留 generated 字符、Unicode map error、bounded text 和原始字体字节。不要从已经去重的 canonical 快照反推原始统计。
- 保留分类所需的 pypdf 文档结构探测；字体资源对象、内容流操作符和嵌套 Form 次数不能替换为字体名称推断。明确分类字体名 UTF-8 ignore 与文本提取 replace 的语义差别。
- 缓存抽样页的去重前原始列或分类摘要，限制驻留；后续窗口消费后释放。消除剩余表格/旋转文本填充的重复物化，并保持显式可变几何输入的优先级。

交付：分类完整统计及最终结果等价；主路径不逐字符往返 Python；快照内存不随文档数量持续增长。

### 4. 完成渲染与取图缓冲（P3）

- 保留定向 open/task/close/ack 协议、文档句柄复用和并发预算；先根据实测分账确定临时像素文件、编码、IPC 与父进程复制的成本。
- 实现独立像素缓冲及带所有者的 NumPy/PIL 适配，验证消费者仍引用时不能提前回收；共享内存超时、取消和崩溃均可清理。
- 合并同页裁图并复用整页图，维持原编码器与栅格参数。局部渲染另批验证 CropBox、旋转、透明度、边缘与像素对齐后再启用。
- 连续处理同时检查实际 OS worker 身份、映射/文件清理、缓冲驻留与完整进程树 RSS，而非仅检查池的内部计数。

交付：像素等价、完整栅格化性能和内存门槛；没有降低清晰度换取速度。

### 5. 整段迁移 Flash 规则（P4）

按照“行与几何 → 表格 → 图形/公式 → 标题段落及阅读顺序 → 跨页判断 → 最终块构造”推进。每次迁移一个能在 Rust 内连续执行的阶段，避免继续增加细碎 Python/Rust 往返。

- 文档级字体、标题、页眉、水印统计仍先于依赖它们的逐页裁决；保留跨页依赖和原始顺序。
- 优先消除重复扫描、重复排序与重复候选构造，候选覆盖、阈值和结果顺序不变。
- 纯迁移提交只要求等价；算法改进另交提交，逐项附原文、前后标框和导出结果，拒绝未解释的质量变化。

交付：`PdfModel.predict()` 的 PDF 分析主流程由 Rust 驱动，Python 仅在输出边界物化 model-list；完整语料与 186 个既有表格区域差分通过。

### 6. 双仓发布收敛（P5）

只有三链路各自满足中位数之和降低至少 50%、无持续单样本超过 5% 退化、峰值 RSS 不超过 130%，且质量和兼容性通过后，才切换默认内核。

- 同步提高 MinerU 的 DocVortex 最低版本，以实际安装 wheel 验证组合；保持 Python 3.10–3.14、ABI3 和跨平台矩阵。
- 保留一个发布周期的显式旧后端选项，计算错误不静默回退；之后退出纯 Python PDF 后端，无扩展时明确报错，其他格式独立运行。
- 更新架构、私有协议、诊断与中文函数说明。合并、发布和默认切换分别作为独立交付状态，不与本机测试通过混称。

若性能目标仍未达到，则交付真实瓶颈、质量证据与差距，保持候选/回退状态，不宣称 P5 完成。
