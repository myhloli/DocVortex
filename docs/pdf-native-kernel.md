# PDF 原生内核迁移

## 验收目标与冻结基线

以 DocVortex `3eef2d1`、MinerU `cabe6e34` 为基线，目标为本机 Mac 单文档热运行耗时降低 50%。公开 parse、MinerU Flash 和冻结模型输入的共享 PDF 链路独立验收；进程树同时刻峰值 RSS 不超过基线 130%（2026-09-27 恢复任务时调整，此前冻结报告仍保留原 120% 门槛），单样本持续耗时退化不超过 5%。冷启动单列，模型推理与导出 PDF 排版不计作本项目的优化收益。

本轮证据根目录为 `output/pdf/native-kernel-20260927/`。源码、原生扩展与输入均独立冻结；32 PDF／299 页包括历史 `49.-.pdf`。`candidate-source` 和 `public-comparison` 是第一批实现，`candidate-stage2` 和 `public-stage2` 是第二批实现，不能混用源码或将前者收益归于后者。

## 当前实现

### 同库读取与连续计算

新增 `docvortex-pdfium` crate，承载原始字符读取、对象树/矩阵/裁剪遍历、路径解码和字体提供器。它借用当前 pypdfium2 的函数和页面，不加载第二份 PDFium，不再次初始化运行库。桥接层先检查 ctypes ABI，再调用同库地址；原有 PDFium 锁仍保护读取操作。

字符原始记录直接在 Rust 中转换坐标，每批至多物化 1024 条 Python 记录。对象树也按有界批次输出，路径端点保留原有共享关系。字体数据及常见回调移入 Rust；非 ASCII 名称的少量字符集判定继续使用 Python 编码语义。回调及释放使用可重入锁，等待锁的绑定方法释放 GIL。实际使用情况和 ABI 回退原因由后端诊断公开。第二批冻结实现的私有协议为 10；后续 run 清洗和句尾迁移使用协议 11。

文本管线将字符组片段、组行、上下标和视觉行准备连接在 Rust 内执行，仅在计算前读取所需字符属性、计算后构造 Python 行。非 ASCII 属性以当前 Python 解释器为准，纯计算期间不回调 Python。特殊可执行对象或不满足精确数值约定的输入保留参考语义。

协议 11 进一步在原生 run 上完成控制字符、软断词和空白清洗，以及句尾和小字号引用判断。Unicode 十进制字符单独使用解释器的 `isdecimal` 属性；粗行回退、空 run 过滤后的原编号及后续跨行合并保持原语义。

表格候选的行中心、边界、成员和来源索引保存在原生候选对象内，连续完成区间划分和成员摘要。候选覆盖、排序、阈值和 HTML 输出规则保持原样。

第二批正式测试发现 `49.-.pdf` 持续退化约 18%，因此该批性能门槛失败。剖析显示每候选重新散列成员和多次身份检查引入了额外开销。修复版将来源 ID 在准备时压缩为连续编号，查询采用独立位图；内部不可变行序列共享已验证区间，外部可变序列仍逐次检查。修复前的证据保留，不用于宣称修复后通过。

### 快照兼容接口

`PDFPage.get_snapshot()` 返回 `PDFPageSnapshot`；文档持有弱缓存。快照独立于原生页面句柄，公开字符、矢量和链接返回独立副本。`prepare_text_evidence`、`prepare_table_page` 接受 `snapshot=`，拒绝错误页面来源及显式几何混用。页面尺寸/旋转仅缓存成功读取值。

协议 12 引入 `NativeTextSnapshot`：字符、去重字体和来源索引由 Rust `Arc` 持有，核心数据不含 Python 对象或 PDFium 指针。原始读取、坐标修复、代理对处理、裁剪、去重和组行连续执行；Flash 直接消费原生视觉行。Python 字符及几何对象仅在兼容接口需要时物化，返回值不反向修改快照。Unicode 属性、字体名称解码和少量浮点兼容元数据按解释器语义去重准备。

`PDFPage.get_text_snapshot()` 提供只读文本入口，不提前提取矢量或链接；`get_snapshot()` 在需要完整页面证据时复用其文本所有权。文档弱缓存不延长快照生命周期，关闭文档后仍可访问已有快照。MinerU 窗口缓存先用轻量行摘要判断方向，再按需升级为完整快照，逐页处理及异常退出时释放缓存。显式传入的可变几何仍遵循原接口，不被内部快照覆盖。

这尚不是完整的 Rust 页面模型：矢量和链接仍保留 Python 兼容存储，文档及页面生命周期仍由 Python 管理，部分表格和旋转文本填充还会读取物化几何。分类、跨页语义与最终块构造没有因此整体迁入 Rust。

### 可选渲染会话

`PDFDocument.get_render_session(threads=..., timeout=...)` 惰性创建文档所有的会话。定向 worker 协议包含打开、任务、关闭、退出和确认。输入 PDF 写入一次，由各 worker 的 PDFium 文件读取器复用文档句柄；关闭确认在句柄释放之后返回。worker 可跨文档复用，共享并发预算；超时、取消和崩溃路径清理资源。原始 PDFium 位图及 stride 通过受控临时文件返回，父进程只做一次必要解码并持有独立 PIL 图像。

通过 `DOCVORTEX_PDF_RENDER_BACKEND=session` 选择新路径，默认仍为 `legacy`。旧按 bytes API 保留兼容，新调用可传 `session=`。MinerU 窗口和补图路径复用文档会话，纯文本 Flash 不提前创建输入文件。异步取消等待渲染任务清理完成。此实现尚不是零复制 NumPy/PIL 或 Rust 像素缓冲。

## 已完成的正确性检查

修复版协议 11 的本地全套结果：Rust 5107 passed / 1 skipped；Python 4617 passed / 491 skipped；MinerU 相关集成 128 passed。Cargo workspace 测试、Clippy（拒绝警告）和格式检查通过。

连续文本直接原生入口覆盖 48 PDF／453 页、1,201,195 字符，逐字段及数值类型检查通过。表格迁移的 32 PDF／299 页 ModelJson、MiddleJson 与冻结基线一致，186 个表格区域的结果、样式 HTML 和诊断一致。测试包含回调重入、字体缓冲、快照关闭后访问、worker 超时/取消/崩溃和关闭失败。

Mac arm64 ABI3 wheel 已构建并通过 CPython 3.14 ABI 检查；独立安装环境的 170 项新内核测试通过。实际安装 DocVortex 与 MinerU 两个 wheel 后，含图的 13 页 `demo1.pdf` Flash 自动文本路径与冻结基线完整一致。测试环境复用本机现有第三方依赖，不代表从零依赖解析或跨平台矩阵已通过。

以上是正确性和本机安装证据，不代表 2 倍性能目标达成，也不代表跨平台 wheel、真实模型及 WebUI 全部验收。

## 协议 11 冻结版本性能

`candidate-stage3`（源码基于 `75f7923`）与原始 Rust 基线逐文档交替运行，一次预热、五次正式测量，并独立采样进程树 RSS。`public-stage3/report.json` 的 32 份公开 `parse()` 输出全部一致；热运行中位数之和为 24.8195 s → 22.4035 s，降低 **9.73%**。最大单文档 RSS 比例为 **1.0335**，没有持续超过 5% 的耗时退化。`49.-.pdf` 在完整轮次中降低 3.21%，先前 18% 的退化未重现。

同一冻结引擎配合 `mineru-stage2` 的实际 Flash 自动文本入口，31 份符合文本分类的 PDF 输出全部一致；`small_ocr.pdf` 按自动分类排除，未强制改为文本。热运行中位数之和为 27.4885 s → 24.2485 s，降低 **11.79%**；最大 RSS 比例 **1.0361**，没有持续超过 5% 的退化。证据为 `flash-stage3/report.json`。

两条链路均**未达到 50% 目标**，不能代替输入栅格化和完整共享路径的验收。协议 12 原生文本快照不在上述冻结版本中，其收益必须另测。

## 协议 12 正确性证据

`text-stage4-parity` 对比纯 Python、原 Rust 字符管线和原生快照：48 PDF／453 页、1,812 种可见性与扩展几何组合的字段、数值类型、别名关系、粗行和视觉行一致。实际执行 1,780 次原生读取，另有 32 个空页组合，无隐式回退；32 PDF／299 页 ModelJson、MiddleJson 也与冻结基线一致。此回放对应二进制摘要 `d9fa33fc…`；随后仅新增 API 与兼容适配的 `06831184…` 另有 113 项专项测试，不将旧二进制回放标为新版本全量回放。

新增 API 版本本机全套为 Rust **5137 passed / 1 skipped**，Python **4620 passed / 518 skipped**。MinerU 专项测试分别为 Rust **184 passed**、Python **182 passed / 2 skipped**。`host-stage4-parity` 的 32 PDF × medium/high 共 64 个回放用例与原基线及协议 11 版本业务输出一致；旧字符几何提取调用由 598 次降为 0。调用次数减少是复用证据，不是耗时收益；实际模型、WebUI 和正式性能仍需分别验收。

## 协议 12 正式性能与暂停

等价静态修复后重建的实际扩展为 `5e946ba774853022b44651a329430a55fb0afa95d6e4d68a684902159418cb78`。格式、严格 Clippy、Cargo 测试及重建后的 203 项快照专项通过。该版源码对应本地 DocVortex `dc0f778` 和 MinerU `bf901490`，冻结副本与最终提交的运行代码逐文件一致。

32 份公开 `parse()` 的逐文档中位数之和为 **21.8964 s → 19.3079 s，降低 11.82%**；31 份实际 Flash 文本路径为 **23.7769 s → 20.8848 s，降低 12.16%**。两者完整输出均一致，无持续超过 5% 的耗时退化，最大进程树 RSS 分别增加 **7.28%** 和 **8.09%**。Flash 的 OCR 样本按实际自动分类排除。

输入栅格化阶段总和为 **6.5079 s → 6.0547 s，降低 6.96%**，32 份像素摘要一致，但 **4 份文档持续退化超过 5%，性能门槛失败**。栅格化不是完整第三条共享链路。独立内存及五次连续处理检查覆盖四个代表样本，均在预算内，worker 和输入资源释放通过；不将有限回放当作长期无泄漏证明。

**2 倍目标未达到，默认渲染器保持 legacy。按用户要求，本轮测试完成后暂停。** 详细原始证据及失败样本见 `output/pdf/native-kernel-20260927/STAGE4-REPORT.md`；恢复顺序见 [后续任务计划](pdf-native-kernel-next.md)。协议 12 提交尚未推送，跨平台 CI、完整共享链路、独立冷启动和发布门槛尚未完成。

## 输入 PDF 基准

`tests/benchmarks/pdf_input.py` 记录分类、字符/矢量读取及真正的输入栅格化，不等同于 `pdf_render.py` 的导出 PDF 排版，也不等同于 MinerU 端到端性能。报告冻结源码/扩展摘要、窗口/进程参数、导入、首次调用及热运行。摘要计算在阶段计时外；`process_wall_seconds` 包含全部运行、检查和退出，不能当作冷启动解析耗时。

`tools/mineru_flash_benchmark.py` 在显式指定的双仓源码上调用实际 `analyze_pdf(effort="flash", parse_mode="auto")`，包括分类、分析、补图、页面几何及关闭。新进程首调用作为唯一预热，再测五次；导入时间单列。另起独立进程预热后采样一次入口 RSS，采样结束才序列化完整结果。自动分类为 OCR 的样本明确排除于 Flash 文本指标，不启动模型或强制改为文本。宿主集成工具放在 `tools`，避免引擎测试引入 MinerU 依赖。
