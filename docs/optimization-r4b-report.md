# R4B OFD 阅读方向与基线投影复用验收报告

日期：2026-10-25。以R4A最终源码为基线，DocVortex保持0.6.1，Rust内核和协议40不变。

**R4B本机验收通过。** 三份目标投影压力输入的公开热耗时中位数之和下降 **26.96%**，51份累计输入完整输出一致。完整测试13199项通过，56份导出输入及同一wheel在Python3.11/3.14的安装验证通过。

16份真实综合输入合计接近持平，真实issue121主测仍有 **+4.96%（约2.37ms）** 成本，低于5%门禁但完整保留。本报告不将压力场景收益推广为所有真实文档的收益。

## 1. 定位和最终实现

在冻结R4A上重新profiling发现：`upright_point` 对同一角度逐字/逐角重算radians、cos、sin及12位round；`merge_paragraph_blocks` 的局部邻域和上下文反复投影同一bbox。先消除这些Python重复工作已取得公开接口收益，因此本批没有增加Rust传输接口或新ABI。

唯一生产修改文件：`src/docvortex/analyzers/native/ofd/assembly.py`。

- `upright_box` 在默认纯数值和标准整数角度下，每个框只计算一次旋转系数，保留原四点顺序、乘零、加法和min/max选择。
- 至少8字形的标准行，一次提取并验证浮点原点，再用同一系数计算基线Y值，仍由Python `statistics.median` 计算原顺序的中位数。短行、整数/定制原点及不支持的数据保留原逐点路径。
- `merge_paragraph_blocks` 内部惰性缓存至多64个不可变数值bbox，按bbox对象身份和角度取键；强引用保存原tuple，避免ID复用，也不合并同值但正负零不同的框。缓存仅活在本次调用，淘汰只影响工作量。
- 原公开 `upright_point` 实现不变；非标准角度、自定义投影/数学/中位数钩子、属性访问及非标准容器保持原行为。阅读顺序、邻域观察范围、分段规则、内容列表所有权及原始输入不变。

没有全局页面缓存，没有原地修改BBox或GlyphItem。64项缓存是固定上限；长行的临时原点引用列表和原有median工作列表仍随本行长度增长，不能称为全流程常数内存。
