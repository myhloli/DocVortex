# 原生内核第五批：渲染退化修复

2026-09-27 恢复任务后按用户要求单代理执行；速度优先，后续 RSS 上限调整为基线的 130%。原始协议 12 报告保留原门槛和失败结果，不回写历史数据。

## 改动与裁决

会话 worker 直接输出 PDFium 原始位图及格式/stride，父进程仅在构造独立 PIL 图像时解码一次。渲染参数、裁图编码器及图像可写性保持不变。输入仍只写一份共享文件，每个定向 worker 按文档复用 PDFium 句柄。

首次实验采用父进程只读 mmap，四份样本仍失败，证据保存在 `input-stage5-focus`。逐行剖析发现本机映射 worker 刚写出的像素文件约需 7 ms，超过约 2 ms 的像素解码；改回普通读取后仍有两份退化，证据为 `input-stage5b-focus`。进一步让 PDFium 直接持有输入文件读取器，避免跨进程新文件 mmap，四份均回到门槛内。正式实现没有增加渲染回退或改变候选覆盖。

原 mmap 导出视图实现被文件句柄所有权替代；仍覆盖 GC 禁用且页面包装被保留、关闭失败、加载失败、重复关闭以及取消/崩溃清理。Windows 的 1 ns 超时测试改用真实 worker 加确定过期 deadline，业务超时未放宽。

## 冻结正式结果

基线为 DocVortex `3eef2d1`，候选源码为 `66f4b5a`，冻结目录 `output/pdf/native-kernel-20260927/candidate-stage5-final`。32 PDF／299 页按文档交替，一次预热、五次正式测量，像素摘要在计时外生成。

- 栅格化阶段中位数之和：**6.426344 s → 4.970703 s，耗时降低 22.65%**。
- 32 份像素和提取摘要全部一致，无单样本超过 5% 的退化，无需反序复测。
- 独立进程树 RSS 及五次连续处理覆盖八份样本：原四份失败样本、demo1、caibao1、small_ocr、中文论文2。候选／基线最大峰值比例为 **0.1611–0.7473**，均低于 1.3；worker 身份稳定且资源释放通过。
- 有限连续回放不代表长期无泄漏；这只是输入栅格化阶段，不代表完整共享 PDF 链路或 2 倍目标达成。

原始证据：`input-stage5-final/report.json`、`input-stage5-summary.json`、`render-memory-stage5-summary.json` 及各样本报告。失败实验、剖析记录和最终结果分别保留。

## 质量与集成

本机渲染回归 51 项通过；灰度、RGB、RGBX、RGBA、字节序、旋转裁剪及 stride 专项包含在内。实际安装的协议 12 ABI3 wheel 通过 CPython 3.14 检查、163 项原生/快照专项、20 项公开 API 检查，以及带图 demo1 的完整 Flash 对照。实际安装双 wheel 的联合检查 **383 passed**。

补齐了快照、渲染会话与共享常量的公开 API 清单。联合 CI 保留隔离解释器及 importlib 导入模式，仅开放测试 helper 目录；过期的整页渲染测试桩同步到实际裁图边界，仍执行真实编码及释放断言。
